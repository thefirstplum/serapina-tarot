# 기술 노트

서비스 운영 중 다룬 주요 기술 과제와 조치 내용, 향후 개선 과제 정리.

## 1. 단일 GPU 환경의 동시 요청 처리

- 현상: 요청이 겹치면 전체 응답이 함께 느려지며 타임아웃 발생. 대기 순번 표시도 간헐적으로만 동작
- 원인: uvicorn `--workers 4` 설정으로 프로세스마다 세마포어가 따로 생성되어, GPU에 최대 4건이 동시에 진입
- 조치: 워커 1개로 통합하고 세마포어로 LLM 호출을 직렬화. 대기 인원을 SSE로 전달해 "앞에 N명 대기 중" 표시

## 2. RAG 검색 결과 미반영

- 현상: 리딩이 전반적으로 일반론에 머물고 카드별 해석이 약함
- 원인: 인덱스가 정규화되지 않은 L2 거리(80~190)를 반환하는데 유사도를 `1 - distance`로 계산해 모든 결과가 임계값에서 탈락. 검색 예외가 `try/except`에서 처리되어 오류로 드러나지 않음
- 조치: 유사도를 코사인으로 직접 계산하도록 변경
- 재발 방지: 기동 시 카드 데이터, 스프레드 정의, RAG 검색, 암호화를 직접 한 번씩 실행해 보는 자체 점검 추가 ([selfcheck.py](../backend/selfcheck.py))
- 함께 확인: 마이너 아르카나 56장 카드 설명 누락. 현재 78장 설명 모두 존재하며, 카드 데이터는 자체 점검 항목에 포함

## 3. 질문 의도와 시간 표현 분리

- 현상: "이번 주에 이직 가능할까?" 같은 질문이 주간 운세로 분류되어 요일별 운세만 출력
- 원인: 시간 표현이 의도보다 우선해 스프레드를 결정
- 조치: 의도를 먼저 판정해 스프레드를 선택하고, 시간 표현은 시기 조정에만 반영 ([question_intent.py](../backend/question_intent.py))

## 4. 긴 스프레드 응답 잘림

- 현상: 5장 스프레드 응답이 중간에 끊김
- 원인: 5장 스프레드 프롬프트가 약 6,900토큰인데 `num_ctx`가 8192로 고정
- 조치: 프롬프트 길이에 맞춰 컨텍스트 크기를 선택하도록 변경

## 5. 위기 표현 감지

- 배경: 청소년 사용자 유입 가능성을 고려해, 자해나 자살 관련 표현 대응을 초기 설계에 포함
- 설계: 명시적 표현은 즉시 처리하고, "시험 죽었어"처럼 오탐 가능성이 있는 표현만 분류 프롬프트(`temperature=0`, YES/NO)로 재확인. 분류 호출에서 예외가 나면 위기로 간주

## 6. 배포 후 재방문자 화면 멈춤

- 현상: API는 정상 응답하는데 재방문자의 화면 전환이 멈춤
- 원인: 서비스워커가 `index.html`까지 캐시 우선으로 처리해, 배포 후 이전 JS 청크를 요청하고 404 발생
- 조치: HTML은 네트워크 우선으로 변경하고, 청크 로드 실패 시 캐시를 비운 뒤 1회 새로고침

## 품질 검증

- 평가 세트: 타로 커뮤니티 실제 질문 499개 (AI가 생성한 질문 세트에서 교체). 3, 4번 이슈는 이 세트로 발견
- 답변 전문 수동 검토: 자동 지표(잘림, 헤지, 문구 중복)로 잡히지 않는 결론 충돌, 단정 표현 확인
- 상세 원칙과 사례: [AI-COLLABORATION.md](AI-COLLABORATION.md)

## 향후 개선 과제

- 자동 회귀 테스트와 CI 도입 (현재 평가 세트를 스크립트로 실행한 뒤 수동 검토, `backend/test_*.py`는 수동 확인용)
- `main.py`(약 3,400줄) 모듈 분리, Ollama와 Anthropic 전환 로직 정리, 구조화 로깅 도입
- PBKDF2 salt 설정값 분리, 위기 분류 호출이 비정상 응답을 받을 때도 위기로 처리하도록 보완
- 결제, 포인트, 카카오 로그인 모듈은 구현 완료 상태이며 운영 미연결
