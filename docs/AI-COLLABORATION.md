## 세션 간 맥락 관리

- `CLAUDE.md`에 구조, 명령어, 운영 절차를 정리해 매 세션 시작 시 로드
- 2026-07부터 세션 종료 시 AI가 작업 기록을 남기고, 모바일에서 단 코멘트를 다음 세션이 우선 반영하는 방식으로 운영
- 작업 기록 규칙
  - 기존 기록은 수정하지 않고 새로 생성 (수정 시 코멘트 유실과 동기화 충돌 발생)
  - 본문 끝에 프로젝트 해시태그 필수 (앱이 본문 태그 기준으로 분류)
  - 다음 할 일은 체크박스로 기록하고, 반영한 코멘트는 "코멘트 반영: ~"으로 표기

## 검증 원칙

- 커뮤니티 실제 질문 499개 전수 실행
- 자동 지표를 통과한 답변에서도 의료 예후 단정, 결론 충돌, 존재하지 않는 인물 생성 사례가 확인되어 답변 전문 수동 검토 도입
- 재검증 시 카드 무작위 추출 (카드를 고정하면 문구 반복이 과대평가됨)
- 기동 시 자체 점검에서 RAG는 로드 여부에 더해 실제 검색까지 수행
- 배포 후 운영 API로 리딩을 생성하고 DB 복호화로 결과 확인 (RAG 인덱스가 이미지에 포함되어 갱신이 반영되지 않은 사례 이후 도입)

## 프롬프트와 분류 개선 사례

- 존재하지 않는 인물 생성: 사람 칸이 있는 스프레드("그 사람의 겉모습" 등)에 일반 질문이 들어오면 모델이 칸을 채우려고 인물을 만들어 냄. 금지 문구 나열 대신 "A/B 중 하나를 한 문장으로 지목" 같은 수행 지시로 바꿔 해결. 수정 후 재검증에서 재발 0회
- 한국어 받침 변형 매칭: `'사귀' in '사귈 거 같아'`가 False가 되는 문제. 키워드를 추가하는 대신 한글 음절 코드 범위(`0xAC00 + (초성×21 + 중성)×28 + 종성`)로 매칭 ([router.py](../backend/experts/router.py)). 키워드 미매칭으로 기본 분류(`daily`)되는 질문 비율 14.8% (499개 기준)
- 부분 해석과 종합 결론의 불일치: 카드별 단락과 종합 결론이 서로 다른 결론을 내는 문제. 상호 정합성 확인 지시를 별도로 추가
- 실사용 질문 분포(242개 기준): 성사 여부 45.5%, 상대 마음 20.2%, 시기 14.5%, 기간 운세 3.3%
